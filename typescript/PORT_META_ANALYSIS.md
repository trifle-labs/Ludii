## Known minefields (☠ — net-negative, do not re-attempt without a new idea)

- ActionMoveStacking full/partial-stack move semantics + ActionAddCount count-transfer OWNER logic (Bashni/Lasca/Moo/Murus/At-Tab).
- `makeFaces()` / board-graph topology / face renumbering (TS's accumulated numbering beats a faithful Java re-port for more games).
- Board TRACK topology (race/* backgammon-family).
- byScore score-COMPUTATION ranking; result-role end-rule resolution (Splade vs Wong/Agapi tension); teams ranking — all part of the deferred end-rule RANKING model.

## Hard gate (every parity change)

build clean + 501/501 unit tests + full 12-shard 90s sweep (`/tmp/sweep.sh`) net-positive + ZERO real regressions (flap distinguished by re-running the game alone) → promote (copy cur shards to baseline) + `check-java-drift --record` + git commit. Bisect bundled changesets; revert anything inert or risky.

## Reflection log (newest first)

### Reflection 10 — 2026-06-01 — **The 1:1 marathon method works: gradient-following porting (COMPILE_FAIL reasons → next targets).**
The 1:1 engine is real and growing fast. Progression in one session: TTT (proof) → 37 (board/space/line) → 44 → **75 board/space OUTCOME_OK via `ENGINE_1TO1`**, with ~141 more games now COMPILE+RUN (MOVE_MISMATCH = debuggable, the "see what's broken" phase). **The method (now T11, ★★★):** run `ENGINE_1TO1=1 … --filter <family>` → the `compiler1to1` COMPILE_FAIL reasons are a *ranked list of the next ludeme classes to port* → fan out an agent to port the top blockers faithfully (class-based, @java-cited, reusing the faithful data builders in `src/eval/graph/**` + `src/state.ts` but NEVER the interpreter dispatch) → gate (build + 1:1 OUTCOME strictly grows + no prior 1:1 game regresses + interpreter path untouched) → commit. Each wave clears the top blocker and exposes the next; ~+30 OUTCOME/wave so far. **Gatekeeping notes that hold:** confine edits to 1:1-path files (then interpreter is provably unaffected — verify via `git status`); when a wave touches a shared-core file (e.g. action-copy), check corpus usage + interpreter spot-check before keeping. **Why this is the right structure:** it's exactly "port every Java file, then see what's broken and debug" (the mandate) but *prioritized by impact* — port the ludemes that unlock the most games first, instead of alphabetically. Two failure modes to watch: (a) unlocking a blocker often just exposes the next (board-shapes wave was only +7 OUTCOME but moved ~88 games COMPILE_FAIL→MM — still progress); (b) MOVE_MISMATCH games need per-ludeme *correctness* debugging later, a separate phase from compile-unblocking. **Next blockers (board/space):** IntFunction (id/sites/var/size) 78, is Connected 28, byScore 24, priority/Select/is-Full/forEach-end ~20 each. The interpreter's 55.2% parity is now a *reference oracle* — when a 1:1 game MOVE_MISMATCHes, diff its 1:1 moves against the interpreter's (which mostly match Java) to localize the bug.

### Reflection 9 — 2026-06-01 — **STRATEGIC RESET (user directive): the goal is a FULL 1:1 Java→TS port; ignore + discard the custom interpreter.**
User: *"the interpreter should also be a 1:1 port of java, not custom built in typescript. do not phase it out, ignore it completely, port every one of the remaining java files, then see what's broken and debug. there is no benefit in preserving broken work that does not follow the goal (1:1 java to ts port)."*

**This reframes everything.** The 55.2% parity was achieved largely through the bespoke `eval/compile.ts` mega-interpreter (+ `lud-compiler.ts`), which has NO Java counterpart — in Java there is no monolithic interpreter; every ludeme is its own class with `eval()`, and a reflection-based Compiler builds the ludeme-object tree. The custom interpreter is therefore "broken work that does not follow the goal" and must be IGNORED, not preserved or incrementally phased out. **The wall I hit was an artifact of polishing the wrong structure.**

**New target architecture (mirror Java exactly):**
- `Language/src/parser` (Parser/Expander/Token) → `Language/src/compiler` (Compiler/Arg*/ArgClass — instantiates ludeme objects from the grammar via constructor-signature matching) → `Core/src/game/**` ludeme classes (each a TS class with faithful `eval()`/move-gen) → `Core/src/other/**` execution core (Context, State, ContainerState, Action*, Trial, Moves, Topology).
- The game plays by: compile `.lud` → ludeme-object tree → `game.start(context)` → loop `game.moves(context)` / `game.apply(context, move)`.

**Scope:** ~1,339 Java files / ~258k lines in Core/src + the Language module. The existing `src/ludemes/**` (752 files, 87.6% class coverage) is the SEED of the 1:1 layer but most are stubs/thin-wrappers that delegate to the interpreter — they must become FULL faithful ports. Java reflection → replaced by an explicit symbol→constructor registry (already partially present).

**Plan:** (1) build a complete per-Java-file manifest with port status (faithful / stub / missing); (2) port the execution-critical path first so a SINGLE simple game (e.g. Tic-Tac-Toe) plays end-to-end through 1:1 objects with the interpreter disabled; (3) fan out parallel agents to port ludeme classes in dependency order, each faithful + @java-cited; (4) run the 2,558-trial harness against the 1:1 engine, see what breaks, debug. Parity will likely DROP first (the interpreter's accidental-correctness is gone) then climb on a faithful foundation. Prior parity-fix techniques (T1/T10) are retired; the new method is **systematic faithful transliteration in dependency order, verified by build + trials.** Multi-session marathon — track via the manifest, not the parity ladder.
